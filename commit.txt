v1.4.4: paste a source folder into the GUI and keep browse dialogs in place

The Input tab's "MP3 Files Location" field now works when you paste a
folder into it, and Browse... no longer jumps back to the default music
directory on every click.

- Paste replaces the field contents instead of splicing the new path
  onto the existing text, and a pasted folder is picked up within about
  half a second: metadata/chapters load, MP3 analysis starts and the
  output directory becomes <folder>/m4b, without needing Enter or a
  focus change (gui/main_window.py, eventFilter, on_source_debounce)
- Normalize pasted paths: surrounding quotes, file:// URLs, stray
  whitespace, multi-line clipboard content and trailing / or \ are all
  handled; ~ and $HOME expand; a pasted file resolves to its parent
  folder; text typed by hand is left untouched while typing
  (_clean_path_text, _source_path_from_text, _tidy_source_field)
- Read the source field through one normalizer (get_source_dir) in
  validate_inputs, create_config_from_gui, scan_batch_directories,
  load_and_analyze_chapters and analyze_mp3_duration, and report
  "Source directory not found: ..." in the status bar for a bad path
- Browse dialogs start where the field points (or the last folder
  chosen) instead of the default music dir: source, chapter file, cover
  image and temp directory

Bump version to 1.4.4; document the changes in README.md.
